# Классификация облаков по спутниковым снимкам

Сверточная нейросеть, которая определяет, какие типы облачных структур есть на спутниковом снимке.

## Задача

На каждом снимке может быть один или несколько из 4 типов облаков - **Sugar**, **Gravel**, **Fish** и **Flower**.

Задача многометочная, для каждого снимка модель отдельно отвечает "есть/нет" по каждому типу. Качество оценивается по коэффициенту Dice.

## Данные

[Understanding Clouds from Satellite Images](https://www.kaggle.com/competitions/understanding_cloud_organization/data) (Kaggle), 5 546 размеченных снимков. 80% использовано для обучения, 20% для проверки.

## Что сделано

1. Исследование данных - частота каждого типа облаков, сколько типов бывает на одном снимке, какие типы встречаются вместе.
2. Основы обучения - градиентный спуск, влияние скорости обучения, взрыв градиента, работа свертки.
3. Простая сверточная сеть с нуля (5 блоков Conv, BatchNorm, ReLU, MaxPool, ~1 млн параметров).
4. Перенос обучения - предобученная ResNet34 (~21 млн параметров) с новым последним слоем на 4 класса.
5. Борьба с переобучением - аугментации, Dropout, сохранение лучшей версии модели.
6. Борьба со взрывом градиента - обрезка градиентов, BatchNorm, уменьшение скорости обучения по расписанию.
7. Подбор порога "есть/нет" для каждого типа облаков.
8. Анализ ошибок модели на примерах снимков.

## Результаты

Модель / Dice

1. Заглушка "всегда есть все 4 типа" - 0.697
2. Простая сверточная сеть (с нуля) - 0.739
3. ResNet34 (предобученная) - 0.760
4. ResNet34 + подобранные пороги - 0.773

### Выводы об облаках

- Flower распознается лучше всего (прирост Dice +0.19 к заглушке).
- Sugar, Gravel и Fish - мелкие и похожие друг на друга узоры, которые часто встречаются вместе. Модель их путает, особенно Gravel с Sugar.
- Flower и Gravel редко встречаются на одном снимке.

## Стек

Python, PyTorch, torchvision, pandas, NumPy, scikit-learn, Matplotlib, Seaborn. Обучение в Google Colab на GPU T4.

## Запуск

Открыть 'Классификация облаков.ipynb' в Google Colab и выполнить все ячейки. Данные скачиваются автоматически в первой ячейке. Случайность зафиксирована ('seed = 42'), поэтому результаты воспроизводятся.
